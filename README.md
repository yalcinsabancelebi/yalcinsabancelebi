### the lab

<sub><code>RESEARCH LOG / ENZO</code></sub>

#### what if a machine had a memory of itself?

**Enzo** is my personal vehicle-intelligence project: a place where backend engineering, telemetry, AI and human–machine interaction meet.

The question is bigger than displaying readings: **how can software learn a particular vehicle's behaviour over time, preserve its history, and use that context meaningfully?**

I'm exploring that through CAN/OBD signals, data capture, replay and evidence-based interpretation.

<details>
<summary><samp>↳ enter the vehicle lab</samp></summary>

<br />

The interesting part starts before the model.

A signal needs context. A capture needs integrity. An interpretation needs evidence. And a claim about a machine needs more than a convincing sentence.

My approach is to preserve raw observations, make experiments replayable and keep the difference between **observed**, **inferred** and **unknown** visible.

| Layer | The question |
| :--- | :--- |
| Capture | What did the machine actually send? |
| Context | Under what conditions did it happen? |
| Replay | Can the observation be examined again? |
| Interpretation | What does the evidence support? |
| Memory | What becomes clearer across repeated observations? |

Enzo is an ongoing research and engineering project. These are the questions guiding it, rather than a list of completed capabilities.
